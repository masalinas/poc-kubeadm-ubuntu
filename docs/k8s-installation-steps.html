1. Arquitectura del Laboratorio

Para simular con fidelidad un entorno de producción sobre una máquina anfitriona Ubuntu 20.04 sin saturar los recursos físicos, se implementa una arquitectura virtualizada aislada compuesta por un nodo Master (Plano de Control) y un nodo Worker.

1.3 Alertas Críticas de Producción (Trampas Habituales)

Advertencia 1: Detección de Interfaz en Red Dual (NAT + Host-Only)
En VirtualBox con red dual, ambas máquinas tienen la misma IP en NAT (10.0.2.15). Tanto kubeadm init como el CNI Flannel deben forzarse a enlazarse a la interfaz Host-Only (enp0s8 / 192.168.56.x). De lo contrario, los nodos intentarán comunicarse por la IP colisionada y el cluster no funcionará.
Advertencia 2: Conflicto de Rangos IP de Pods (CIDR)
La red de pods se establece en 10.244.0.0/16. Si se utiliza el rango por defecto de Calico (192.168.0.0/16) sobre una red Host-Only 192.168.56.0/24, colisionan y se produce un fallo de enrutamiento grave.
Importante: Repositorio Oficial Moderno (pkgs.k8s.io)
Los antiguos repositorios apt.kubernetes.io de Google están deprecados y retirados. Toda instalación debe apuntar a la clave y repositorio comunitario oficial en https://pkgs.k8s.io/core:/stable:/v1.31/deb/.

2. Sección 1: Despliegue Manual Paso a Paso con Kubeadm

Objetivo pedagógico: Comprender en profundidad cada capa del sistema, kernel, runtime de contenedores y red interna.

2.1 Creación de la Red Solo-Anfitrión en VirtualBox (vboxnet0)

Antes de crear o iniciar las máquinas virtuales, es indispensable aprovisionar la red privada aislada (Host-Only) en VirtualBox que interconectará el nodo de control, el worker y la máquina anfitriona.

  1. En la ventana principal de VirtualBox, accede al menú: Archivo -> Herramientas -> Administrador de red de host (o la pestaña lateral Herramientas -> Redes).
  2. Haz clic en el botón + (Crear) para generar una nueva red sólo-anfitrión. Por defecto se creará con el nombre vboxnet0.
  3. Selecciona vboxnet0 y configura sus parámetros en la pestaña Adaptador:
    • Dirección IPv4: 192.168.56.1
    • Máscara de red IPv4: 255.255.255.0 (/24)
  4. En la pestaña Servidor DHCP: Desmarca la casilla Habilitar servidor (recomendado), ya que asignaremos direccionamiento estático persistente mediante Netplan en cada máquina virtual.
  5. Haz clic en Aplicar.

2.2 Creación y Configuración de VMs en VirtualBox 7.0

Descarga la imagen oficial para servidores de Ubuntu 22.04 LTS (Jammy Jellyfish):

  • URL de descarga: https://releases.ubuntu.com/22.04/ubuntu-22.04.5-live-server-amd64.iso

Crea dos máquinas virtuales en la interfaz gráfica de VirtualBox respetando estrictamente los siguientes parámetros:

  • k8s-master: 2 vCPUs, 3072 MB RAM, 25 GB de disco dinámico VDI.
  • k8s-worker1: 2 vCPUs, 2048 MB RAM, 20 GB de disco dinámico VDI.
  • Configuración de red en ambas VMs:
    • Adaptador 1: Conectado a NAT (salida a internet para descargar paquetes).
    • Adaptador 2: Conectado a Adaptador sólo-anfitrión (Host-Only) (nombre: vboxnet0, modo promiscuo: Permitir todo).
Atención al clonar máquinas
Si instalas el Master y lo clonas para crear el Worker, marca obligatoriamente: "Generar nuevas direcciones MAC para todos los adaptadores de red". Si tienen la misma MAC, la red fallará.

2.3 Configuración de Idioma y Teclado Español

Por defecto, Ubuntu Server se instala con la distribución de teclado en inglés (US). Esto genera errores de tipeo al introducir caracteres frecuentes de administración en consola como guiones (-), tuberías (|), barras (/), almohadillas (#) o comillas.

Ejecuta en ambos nodos (k8s-master y k8s-worker1) nada más iniciar sesión:

# 1. Configurar la distribución de teclado a español pc105 de forma persistente
sudo localectl set-x11-keymap es pc105

# 2. Cargar el mapa de teclado en la consola actual de manera inmediata
sudo loadkeys es

localectl persiste la configuración en /etc/default/keyboard para todos los futuros arranques, mientras que loadkeys es aplica la tabla de teclas de inmediato en la sesión TTY actual.

2.4 Persistencia de Red: Bloqueo de Cloud-Init y Netplan Estático

En Ubuntu Server 22.04 LTS, el servicio cloud-init gestiona la configuración de red y reescribe los archivos de Netplan al reiniciar el sistema. Si se modifica Netplan sin desactivar la generación de red de cloud-init, la dirección IP estática se perderá tras reiniciar la máquina virtual.

2.4.1 Crear archivo de bloqueo para cloud-init (Ambos Nodos)

Ejecuta en k8s-master y k8s-worker1:

sudo touch /etc/cloud/cloud-init.disabled

2.4.2 Configurar Netplan con IP Estática

Edita el archivo /etc/netplan/50-cloud-init.yaml en el nodo k8s-master:

network:
  ethernets:
    enp0s3:
      dhcp4: true
      optional: true
    enp0s8:
      dhcp4: false
      addresses:
      - 192.168.56.10/24
      optional: true
  version: 2

Edita el archivo /etc/netplan/50-cloud-init.yaml en el nodo k8s-worker1:

network:
  ethernets:
    enp0s3:
      dhcp4: true
      optional: true
    enp0s8:
      dhcp4: false
      addresses:
      - 192.168.56.11/24
      optional: true
  version: 2

2.4.3 Aplicar los cambios de red

sudo netplan apply

2.5 Preparación Base del Sistema Operativo (SWAP, Kernel y Sysctl)

Ejecuta los siguientes pasos en ambas máquinas virtuales:

2.5.1 Desactivación Permanente de SWAP

sudo swapoff -a
sudo sed -i '/^\/swap\.img/ s/^/#/' /etc/fstab
swapon --show  # Debe devolver salida vacía

2.5.2 Módulos de Kernel y Sysctl

cat <<EOF | sudo tee /etc/modules-load.d/k8s.conf
overlay
br_netfilter
EOF

sudo modprobe overlay
sudo modprobe br_netfilter

cat <<EOF | sudo tee /etc/sysctl.d/k8s.conf
net.bridge.bridge-nf-call-iptables  = 1
net.bridge.bridge-nf-call-ip6tables = 1
net.ipv4.ip_forward                 = 1
EOF

sudo sysctl --system

2.6 Instalación de Containerd y Dependencias del Sistema (conntrack, socat)

Desde Kubernetes v1.24, el subsistema dockershim fue removido. Instalaremos containerd como runtime estándar de contenedores (CRI), junto con dos paquetes fundamentales del sistema operativo:

  • conntrack: Requerido por kube-proxy y kubelet para gestionar y monitorear las tablas de seguimiento de conexiones de iptables/netfilter. Sin conntrack, la asignación de IPs virtuales de servicio y balanceo de tráfico falla.
  • socat: Utilizado por el API Server de Kubernetes para canalizar flujos de entrada/salida y crear túneles bidireccionales, indispensables para el correcto funcionamiento de comandos como kubectl exec y kubectl port-forward.

Ejecuta en ambos nodos (k8s-master y k8s-worker1):

sudo apt-get update
sudo apt-get install -y containerd conntrack socat

sudo mkdir -p /etc/containerd
containerd config default | sudo tee /etc/containerd/config.toml > /dev/null

# Habilitar SystemdCgroup (Obligatorio para evitar discrepancias con kubelet)
sudo sed -i 's/SystemdCgroup = false/SystemdCgroup = true/g' /etc/containerd/config.toml

sudo systemctl restart containerd
sudo systemctl enable containerd
sudo systemctl status containerd --no-pager

2.7 Instalación de Herramientas Kubernetes v1.31 (pkgs.k8s.io)

Ejecuta en ambos nodos:

# 1. Instalar dependencias de transporte seguro
sudo apt-get update
sudo apt-get install -y apt-transport-https ca-certificates curl gpg

# 2. Crear directorio de llaveros de confianza
sudo mkdir -p -m 755 /etc/apt/keyrings

# 3. Descargar y almacenar la clave pública oficial de Kubernetes v1.31
K8S_REPO="https://pkgs.k8s.io/core:/stable:/v1.31/deb/"
KEYRING="/etc/apt/keyrings/kubernetes-apt-keyring.gpg"

curl -fsSL "${K8S_REPO}Release.key" \
  | sudo gpg --dearmor -o "${KEYRING}"

# 4. Registrar el repositorio comunitario oficial
echo "deb [signed-by=${KEYRING}] ${K8S_REPO} /" \
  | sudo tee /etc/apt/sources.list.d/kubernetes.list

# 5. Instalar kubelet, kubeadm y kubectl
sudo apt-get update
sudo apt-get install -y kubelet kubeadm kubectl

# 6. Bloquear actualizaciones automáticas para preservar estabilidad
sudo apt-mark hold kubelet kubeadm kubectl
Solución de Problemas: Error de validación de claves en apt update

Si durante la instalación o actualización de paquetes con apt el repositorio no es reconocido por Ubuntu o se presentan errores con firmas de claves públicas (por ejemplo, errores de claves no válidas o ausentes en repositorios como HashiCorp preexistentes en la máquina virtual, p. ej. NO_PUBKEY AA16FCBCA621E701), la solución consiste en añadir la clave al keyring (sin utilizar apt-key, que se encuentra obsoleto):

gpg --no-default-keyring --keyring /tmp/hc-old.gpg --keyserver keyserver.ubuntu.com --recv-keys AA16FCBCA621E701
gpg --no-default-keyring --keyring /tmp/hc-old.gpg --export | sudo tee -a /usr/share/keyrings/hashicorp-archive-keyring.gpg > /dev/null
sudo apt update

2.8.4 Desplegar CNI Flannel con fijación de interfaz

Descarga el manifiesto oficial de Flannel:

FLANNEL_URL="https://github.com/flannel-io/flannel/releases/latest/download/kube-flannel.yml"
curl -sSL "${FLANNEL_URL}" -o kube-flannel.yml

Añade el argumento --iface=enp0s8 para que Flannel se comunique por la red Host-Only. Puedes aplicarlo automáticamente con sed:

sed -i 's/- --kube-subnet-mgr/- --kube-subnet-mgr\n        - --iface=enp0s8/' kube-flannel.yml

O editar manualmente con nano kube-flannel.yml para que la sección args quede así:

      containers:
      - name: kube-flannel
        image: docker.io/flannel/flannel:...
        command:
        - /opt/bin/flanneld
        args:
        - --ip-masq
        - --kube-subnet-mgr
        - --iface=enp0s8

Aplica el manifiesto modificado:

kubectl apply -f kube-flannel.yml

kubectl get nodes
kubectl get pods -n kube-system

2.10 Conexión Remota No Destructiva desde el Host Anfitrión (Merge Kubeconfig)

Precaución: No sobrescribas tu archivo ~/.kube/config
Si ya utilizas Kubernetes en tu equipo host (ej. Minikube, Docker Desktop, k3s, EKS, GKE), ejecutar scp ... ~/.kube/config destruirá tus contextos y configuraciones preexistentes. A continuación se detalla cómo fusionar la nueva configuración de forma segura y no destructiva.

2.10.1 Instalar herramientas base en el terminal del Host (Ubuntu 20.04)

sudo apt-get update && sudo apt-get install -y \
  apt-transport-https ca-certificates curl gpg

sudo mkdir -p -m 755 /etc/apt/keyrings

K8S_REPO="https://pkgs.k8s.io/core:/stable:/v1.31/deb/"
KEYRING="/etc/apt/keyrings/kubernetes-apt-keyring.gpg"

curl -fsSL "${K8S_REPO}Release.key" \
  | sudo gpg --dearmor -o "${KEYRING}"

echo "deb [signed-by=${KEYRING}] ${K8S_REPO} /" \
  | sudo tee /etc/apt/sources.list.d/kubernetes.list

sudo apt-get update && sudo apt-get install -y kubectl

2.10.2 Descargar el archivo kubeconfig del Master a un fichero local

mkdir -p ~/.kube
scp <usuario>@192.168.56.10:~/.kube/config ./master-kubeconfig

Alternativa A: Fusión Automática con kubectl (Recomendada)

3.4 Scripts de Aprovisionamiento Modular

3.4.1 Script Común: scripts/common.sh

#!/bin/bash
set -euo pipefail
export DEBIAN_FRONTEND=noninteractive

# 1. Hosts y resolución
cat <<EOF >> /etc/hosts
192.168.56.10 k8s-master
192.168.56.11 k8s-worker1
EOF

# 2. Swap off permanente
swapoff -a
sed -i '/^\/swap\.img/ s/^/#/' /etc/fstab

# 3. Carga de módulos de kernel
cat <<EOF > /etc/modules-load.d/k8s.conf
overlay
br_netfilter
EOF
modprobe overlay && modprobe br_netfilter

# 4. Parámetros Sysctl
cat <<EOF > /etc/sysctl.d/k8s.conf
net.bridge.bridge-nf-call-iptables  = 1
net.bridge.bridge-nf-call-ip6tables = 1
net.ipv4.ip_forward                 = 1
EOF
sysctl --system > /dev/null

# 5. Containerd y dependencias de red indispensables
apt-get update -y > /dev/null
apt-get install -y containerd apt-transport-https ca-certificates curl gpg conntrack socat > /dev/null
mkdir -p /etc/containerd
containerd config default > /etc/containerd/config.toml
sed -i 's/SystemdCgroup = false/SystemdCgroup = true/g' /etc/containerd/config.toml
systemctl restart containerd && systemctl enable containerd > /dev/null

# 6. Kubernetes v1.31 (pkgs.k8s.io)
K8S_REPO="https://pkgs.k8s.io/core:/stable:/v1.31/deb/"
KEYRING="/etc/apt/keyrings/kubernetes-apt-keyring.gpg"
mkdir -p -m 755 /etc/apt/keyrings
curl -fsSL "${K8S_REPO}Release.key" | gpg --dearmor --yes -o "${KEYRING}"
echo "deb [signed-by=${KEYRING}] ${K8S_REPO} /" \
  > /etc/apt/sources.list.d/kubernetes.list

apt-get update -y > /dev/null
apt-get install -y kubelet kubeadm kubectl > /dev/null
apt-mark hold kubelet kubeadm kubectl > /dev/null

3.4.2 Script del Master: scripts/master.sh

#!/bin/bash
set -euo pipefail
MASTER_IP="192.168.56.10"
POD_CIDR="10.244.0.0/16"

kubeadm config images pull > /dev/null
kubeadm init \
  --apiserver-advertise-address="${MASTER_IP}" \
  --pod-network-cidr="${POD_CIDR}" \
  --node-name k8s-master > /dev/null

mkdir -p /home/vagrant/.kube /root/.kube /vagrant_configs
cp -i /etc/kubernetes/admin.conf /home/vagrant/.kube/config
cp -i /etc/kubernetes/admin.conf /vagrant_configs/config
chown -R vagrant:vagrant /home/vagrant/.kube
chmod 644 /vagrant_configs/config

# Flannel CNI
FLANNEL_URL="https://github.com/flannel-io/flannel/releases/latest/download/kube-flannel.yml"
curl -sSL "${FLANNEL_URL}" -o /tmp/kube-flannel.yml
sed -i 's/- --kube-subnet-mgr/- --kube-subnet-mgr\n        - --iface=enp0s8/' /tmp/kube-flannel.yml
kubectl --kubeconfig=/etc/kubernetes/admin.conf apply -f /tmp/kube-flannel.yml > /dev/null

# Generar join command para el worker
kubeadm token create --print-join-command > /vagrant_configs/join.sh
chmod +x /vagrant_configs/join.sh

5. Resolución de Problemas Frecuentes (Troubleshooting)

Fallo 1: "The connection to the server 10.0.2.15:6443 was refused"
Causa: No se especificó --apiserver-advertise-address=192.168.56.10 en kubeadm init y el plano de control intentó anunciarse por la IP NAT.
Solución: Ejecutar sudo kubeadm reset -f en el master y volver a inicializar añadiendo explícitamente el parámetro de dirección.
Fallo 2: "CoreDNS en estado Pending o CrashLoopBackOff"
Causa: El CNI no se ha instalado o Flannel eligió la interfaz incorrecta.
Solución: Verificar que Flannel tiene inyectado - --iface=enp0s8. Comprobar los logs de los pods de Flannel con kubectl logs -n kube-system -l k8s-app=flannel.
Fallo 3: "kubelet fails with cgroup driver mismatch"
Causa: Containerd no tiene activado SystemdCgroup = true en /etc/containerd/config.toml.
Solución: Modificar el archivo de configuración de containerd y reiniciar con sudo systemctl restart containerd && sudo systemctl restart kubelet.
Fallo 4: "El worker no puede conectarse al puerto 6443 del master"
Causa: El cortafuegos local (UFW) de Ubuntu Server está bloqueando el tráfico en la red privada.
Solución: En el master ejecutar sudo ufw allow 6443/tcp o deshabilitarlo para el laboratorio con sudo ufw disable.
